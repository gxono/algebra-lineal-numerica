# Problema 5.6 - `matvec` sin construir la matriz

## Enunciado

> Crear una función `matvec` que para cada vector $x$ devuelva el resultado de $Ax$, sin realizar el producto de manera explícita, donde
> $$A = \begin{pmatrix}2&-1&&&\\-1&2&-1&0&\\&-1&2&-1&\\&&\ddots&\ddots&\ddots\\&0&&-1&2\end{pmatrix}.$$
> Ayuda: tratar de interpretar la acción de $A$ sobre un vector dado $x$, y "transformarlo" según esta acción sin utilizar la matriz $A$.

Para $A=\text{tridiag}(-1,2,-1)\in\mathbb{R}^{n\times n}$, interpretar la acción de $A$ sobre $x$ directamente:
$$
(Ax)_i = -x_{i-1}+2x_i-x_{i+1} \quad(\text{con } x_0=x_{n+1}=0).
$$

```julia
function matvec(x::AbstractVector)
    n = length(x)
    y = similar(x)
    y[1] = 2x[1] - x[2]
    for i in 2:n-1
        y[i] = -x[i-1] + 2x[i] - x[i+1]
    end
    y[n] = -x[n-1] + 2x[n]
    return y
end
```

Costo $O(n)$ (3 operaciones por componente), contra $O(n^2)$ de un producto matriz-vector denso genérico, y sin necesidad de almacenar la matriz ($O(1)$ memoria extra en vez de $O(n^2)$ o incluso $O(n)$ de una `Tridiagonal`).

## Por qué importa

Esta es exactamente la idea que permite usar [[Implementacion del gradiente conjugado|GC]] y [[GMRes - implementacion y rotaciones de Givens|GMRes]] con matrices que ni siquiera existen explícitamente ($A$ *matrix-free*): ambos algoritmos solo necesitan la acción $ξ\to A\xi$, nunca las entradas de $A$ por separado (ver la nota correspondiente en [[Descenso mas pronunciado]]).
