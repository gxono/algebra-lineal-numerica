# Problema 2.8 - Inestabilidad de Gauss sin [[Pivoteo y matrices de permutacion|pivoteo]]

## Enunciado

> Considerar $A=\begin{pmatrix}\delta&1\\1&1\end{pmatrix}$ y $b=\begin{pmatrix}1+\delta\\2\end{pmatrix}$.
> **(a)** Hallar la solución exacta de $Ax=b$ para $\delta\neq1$.
> **(b)** Resolver el mismo sistema utilizando las funciones `eleu`, `triinf_cols` y `trisup`, para los valores de $\delta=10^{-2},10^{-4},10^{-6},\dots,10^{-18}$. Armar una tabla de la forma
> ```
> delta      x(1)    x(2)
> -----------------------------
> 10^(-2)    xxxx    xxxx
> ...
> ...
> ```
> Explicar qué sucede (Ayuda: pensar qué ocurre con los errores de redondeo al hacer la eliminación de Gauss.)

> [!idea]
> El ejemplo numérico que justifica *por qué* hace falta pivotear: con un pivote chico, los multiplicadores se vuelven gigantes y amplifican el error de redondeo.

Sistema: $A=\begin{bmatrix}δ&1\\1&1\end{bmatrix}$, $b=(1+δ,2)$.

## (a) Solución exacta

Restando las dos ecuaciones ($δx+y=1+δ$ y $x+y=2$): $(δ-1)x = δ-1$, y como $δ≠1$, $x=1$, $y=1$. **La solución exacta es $(1,1)$ para cualquier $δ≠1$.**

## (b) Resolviendo sin pivotear, para $δ=10^{-2},10^{-4},\dots,10^{-18}$

```julia
function calcula_solucion_28(δ)
    A = [δ 1.0; 1.0 1.0]
    b = [1+δ, 2.0]
    L, U = eleu(A)                  # sin pivoteo
    y = triinf(L, b)
    return trisup(U, y)
end

for i in 2:2:18
    @show calcula_solucion_28(10.0^(-i))
end
```

**Qué se observa:** para $δ$ grande ($10^{-2}$), el resultado es correcto ($≈(1,1)$). A medida que $δ$ se achica, $x[1]$ se degrada cada vez más, y para $δ≤10^{-16}$ (del orden de $ε_maq$) el resultado puede ser completamente erróneo (incluso $NaN$ o un valor muy lejos de $1$).

## Por qué ocurre (la explicación que pide el enunciado)

Sin pivotear, el pivote de la primera columna es $δ$ (chico), y el multiplicador es $m=1/δ$ (**gigante**). Al eliminar:
$$
U_{22} = 1 - \frac1\delta\cdot1 = 1-\frac1\delta, \qquad y_2 = 2-\frac1\delta(1+\delta) = 1-\frac1\delta.
$$
Para $δ$ chico, $1/δ$ es enorme, y en punto flotante **el $1$ se pierde en el redondeo**: tanto $U_{22}$ como $y_2$ quedan calculados con un error absoluto $≈ε_{maq}·(1/δ)$, no $≈ε_{maq}$. Al dividir, $x_2=y_2/U_{22}$ sigue dando $≈1$ (el error relativo se cancela parcialmente), pero el daño ya está hecho: al despejar $x_1=(1+δ-x_2)/δ$, la cantidad $1+δ-x_2$ debería ser $≈0$, pero tiene un error absoluto heredado del paso anterior; **dividir ese error por $δ$ (chico) lo amplifica por un factor $1/δ$**. Así, el error en $x_1$ crece sin control a medida que $δ→0$.
