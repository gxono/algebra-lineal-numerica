# Problema 2.2 - Comparar tiempos de `triinf`, `triinf_filas`, `triinf_cols`

## Enunciado

> Utilizando las funciones `tic` y `toc` de matlab/octave, comparar los tiempos de ejecución de las funciones `triinf`, `triinf_filas` y `triinf_cols` para la resolución de sistemas lineales con matrices triangulares inferiores.

> [!idea]
> Las tres variantes (acceso genérico, por filas, por columnas) hacen el **mismo número** de operaciones ($n²$, ver [[Matrices triangulares - sustitucion]]), pero **no** tardan lo mismo: lo que cambia es el patrón de acceso a memoria.

`triinf` ([[Matrices triangulares - sustitucion]]) ya está vectorizada con `dot`/`@view`; para comparar patrones de acceso a memoria hacen falta además las dos variantes con bucles explícitos:

```julia
using BenchmarkTools, LinearAlgebra

function triinf_filas(L, b)        # acceso explícito por filas (recorre L[i,:] para cada i)
    n = length(b)
    x = copy(b)
    for i in 1:n
        s = 0.0
        for j in 1:i-1
            s += L[i,j] * x[j]
        end
        x[i] = (b[i] - s) / L[i,i]
    end
    return x
end

function triinf_cols(L, b)         # acceso explícito por columnas (actualiza el resto de x al procesar cada columna)
    n = length(b)
    x = copy(b)
    for j in 1:n
        x[j] /= L[j,j]
        for i in j+1:n
            x[i] -= L[i,j] * x[j]
        end
    end
    return x
end

N = 1000
LT = tril(rand(N, N))
b = rand(N)

@benchmark triinf($LT, $b)            # genérico (vectorizado con dot/@view)
@benchmark triinf_filas($LT, $b)      # acceso explícito por filas
@benchmark triinf_cols($LT, $b)       # acceso explícito por columnas
```

## Conclusión

En Julia, las matrices densas se guardan **column-major** (una columna es contigua en memoria). Por eso la versión que accede por columnas (`triinf_cols`) suele ser la más rápida: cada operación toca un bloque contiguo de memoria, lo cual aprovecha mejor la caché del procesador. La versión por filas salta de a un elemento por columna ($L[i, 1:i-1]$), lo cual es más costoso en términos de localidad de memoria aunque el conteo de operaciones sea idéntico.

> [!pendiente]
> En Julia esta diferencia es **mucho menor** que en MATLAB/Octave, porque Julia compila cada función la primera vez que se ejecuta (JIT): un bucle bien tipado con $@inbounds$/$@simd$/$@views$ puede llegar a competir con las versiones vectorizadas por columnas. En MATLAB/Octave, en cambio, evitar bucles explícitos (vectorizar) suele ser mucho más determinante.
