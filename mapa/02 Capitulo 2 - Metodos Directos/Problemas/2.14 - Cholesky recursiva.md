# Problema 2.14 - [[Factorizacion de Cholesky|Cholesky]] recursiva

## Enunciado

> Programar una versión recursiva de la factorización de Cholesky. Comparar el funcionamiento de ésta con el de la función `cholesky` dada en clase para matrices de diferentes órdenes de la forma
> $$A = \begin{pmatrix}2&-1&&&\\-1&2&-1&0&\\&-1&2&-1&\\&&\ddots&\ddots&\ddots\\&0&&-1&2\end{pmatrix}.$$

> [!idea]
> La demostración del [[Factorizacion de Cholesky|teorema de Cholesky]] es *constructiva por inducción*: factoriza la primera fila/columna y reduce el problema a una submatriz de tamaño $n-1$. Programarla recursivamente es casi una transcripción literal de la demostración.

```julia
"""
    mi_cholesky!(A::AbstractMatrix)

Versión recursiva: factoriza la primera fila/columna (ρ=√A[1,1], resto de
la fila dividido por ρ), actualiza la submatriz A[2:n,2:n] -= r*r', y
se llama a sí misma sobre esa submatriz.
"""
function mi_cholesky_recursiva!(A::AbstractMatrix)
    n = size(A, 1)
    if n == 1
        A[1,1] = sqrt(A[1,1])
        return A
    end

    ρ = sqrt(A[1,1])
    A[1,1] = ρ
    A[1, 2:n] ./= ρ
    A[2:n, 1] .= 0
    @views A[2:n, 2:n] .-= A[1, 2:n] * A[1, 2:n]'
    @views mi_cholesky_recursiva!(A[2:n, 2:n])
    return UpperTriangular(A)
end
```

Para el caso particular **tridiagonal** (como la matriz `tridiag(-1,2,-1)` del problema), no hace falta operar con la submatriz completa: alcanza con actualizar dos escalares por paso, porque el resto de la submatriz ya es cero fuera de la tridiagonal:

```julia
function mi_cholesky_tridiag!(M::Tridiagonal; niv=1)
    n = size(M, 1)
    if niv == n
        M.d[niv] = sqrt(M.d[niv])
        return Bidiagonal(M, :U)
    end
    ρ = sqrt(M.d[niv])
    M.d[niv] = ρ
    M.du[niv] /= ρ
    M.d[niv+1] -= M.du[niv]^2
    return mi_cholesky_tridiag!(M, niv=niv+1)
end
```

## Comparación con la versión iterativa

Son **exactamente el mismo algoritmo** (misma cantidad de operaciones, $n³/3$ para la versión densa, $O(n)$ para la tridiagonal): la recursión solo reorganiza el control de flujo, reemplazando el `for` por llamadas a sí misma. En Julia, la versión recursiva puede ser levemente más lenta por el overhead de las llamadas a función (que el compilador JIT en general logra eliminar vía *inlining* si la recursión no es demasiado profunda), pero para matrices chicas a medianas la diferencia es despreciable. La versión tridiagonal recursiva, al evitar tocar entradas que ya son cero, es la más eficiente de todas ($O(n)$ con una constante muy chica).
