# Problema 2.3 - Resolver varios sistemas triangulares a la vez

## Enunciado

> Considerar la función `triinf_cols` para resolver sistemas triangulares inferiores, y basándose en esto, crear la función `triinfm` que resuelva varios sistemas simultáneamente. Más precisamente, si $L$ es una matriz triangular inferior y $b$ es una matriz cuyas columnas representan varios términos independientes, entonces `x=triinfm(L,b)` resuelve los distintos sistemas donde la $j$-ésima columna de $x$ contiene la solución del sistema cuyo lado derecho es la $j$-ésima columna de $b$.

> [!idea]
> Si hay que resolver $Lx=b$ para varios lados derechos $b$ (las columnas de una matriz $B$), conviene una función que reciba $B$ entera en vez de llamar a `triinf` columna por columna desde afuera: así se puede optimizar el acceso a memoria conjunto.

```julia
"""
    triinfm(L, B)

Si L es triangular inferior y las columnas de B son varios lados derechos,
devuelve X cuya columna j es la solución de L*x = B[:,j].
"""
function triinfm(L::AbstractMatrix{T}, B::AbstractMatrix{T}) where T
    n, cb = size(B)
    X = copy(B)
    @inbounds begin
        X[1, :] ./= L[1, 1]
        for i in 2:n
            for c in 1:cb
                xi = X[i-1, c]
                @simd for k in i:n
                    X[k, c] -= xi * L[k, i-1]
                end
            end
            X[i, :] ./= L[i, i]
        end
    end
    return X
end
```

## Por qué no alcanza con un `for` que llame a `triinf_cols` por cada columna de $B$

Funcionalmente es equivalente (y es una primera versión razonable), pero resolver todas las columnas *a la vez*, actualizando la matriz $X$ completa en cada paso $i$ (en vez de columna por columna de punta a punta), permite reusar mejor los datos de $L$ que ya están en caché, y es lo que hace `triinfm_opt` en el cuaderno. En la práctica, para $B$ con pocas columnas la diferencia es chica; para muchas columnas (resolver muchos sistemas con la misma matriz), conviene la versión conjunta.
