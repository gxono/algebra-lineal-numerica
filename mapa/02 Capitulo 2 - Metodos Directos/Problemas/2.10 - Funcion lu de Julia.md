# Problema 2.10 - La función `lu` de Julia

## Enunciado

> Investigar cómo funciona la función `lu` de matlab/octave. Comparar con la función `eleupiv`.
>
> *(Adaptado a Julia en esta vault: comparar con `LinearAlgebra.lu`.)*

> [!idea]
> `LinearAlgebra.lu(A)` es, conceptualmente, exactamente `eleupiv` (LU con [[Pivoteo y matrices de permutacion|pivoteo]] parcial), pero con una interfaz de objeto (`LU`) y usando LAPACK por detrás (mucho más rápido y robusto que una implementación "a mano").

```julia
using LinearAlgebra
A = [2.0 1 -1; -2 -10 0; -1 -1 4]
F = lu(A)       # F :: LU{Float64, Matrix{Float64}, Vector{Int64}}

F.L        # triangular inferior unitaria
F.U        # triangular superior
F.p        # vector de permutación (equivalente al p de eleupiv)
F.P        # matriz de permutación explícita

A[F.p, :] ≈ F.L * F.U       # true
```

## Comparación con `eleupiv`

| | `eleupiv` (nuestra) | `lu` (Julia/LAPACK) |
|---|---|---|
| Algoritmo | Gauss con pivoteo parcial | el mismo algoritmo |
| Implementación | Julia puro, sin optimizar a bajo nivel | LAPACK (Fortran, décadas de optimización: bloqueo por caché, BLAS nivel 3, multi-hilo) |
| Uso típico | entender el algoritmo | uso real: resolver sistemas (`A \ b` lo usa por detrás), reutilizar factorización |
| Resolver con la factorización | `trisup(U, triinf(L, b[p]))` | `F \ b` (hace lo mismo automáticamente) |

`A \ b`, para una matriz densa cuadrada genérica, internamente llama a `lu(A)` y resuelve con esa factorización. Por eso **nunca** conviene escribir `inv(A)*b` (ver [[Resolver sistemas lineales en Julia]]): `lu` ya hace exactamente lo necesario, de forma estable y eficiente.
