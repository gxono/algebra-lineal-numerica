# Problema 2.4 - `trisup` reusando `triinf`

## Enunciado

> Basándose en la función `triinf_cols`, crear la función `trisup` para resolver sistemas lineales de matrices triangulares superiores.

> [!idea]
> Resolver $Ux=b$ con $U$ triangular superior es "lo mismo" que resolver un sistema triangular inferior, si se invierte el orden de filas y columnas. Es un truco elegante pero no es la forma más eficiente (ver nota al final).

```julia
"""
    trisup_via_triinf(U, b)

Resuelve Ux=b reutilizando triinf_cols, invirtiendo filas y columnas.
"""
function trisup_via_triinf(U::AbstractMatrix{T}, b::AbstractVector{T}) where T
    x = triinf_cols(U[end:-1:1, end:-1:1], b[end:-1:1])
    return reverse(x)
end
```

**Por qué funciona:** si $U$ es triangular superior, invertir el orden de filas *y* columnas la convierte en triangular inferior (la entrada $(i,j)$ con $i≤j$ de $U$ pasa a la posición $(n+1-i, n+1-j)$, y $n+1-i ≥ n+1-j$, o sea queda por debajo o sobre la diagonal de la matriz invertida). Resolver ese sistema triangular inferior y después invertir el orden del resultado da la solución de $Ux=b$.

> [!pendiente]
> Esta no es la implementación más eficiente: construir $U[end:-1:1, end:-1:1]$ genera una vista invertida que no siempre es tan amigable con la caché como recorrer $U$ directamente de abajo hacia arriba (como hace `trisup` en [[Matrices triangulares - sustitucion]]). Es un buen truco para no duplicar código, no necesariamente para producción.
